# シフト自動作成デモアプリ 要件定義書

## 1. 文書情報

- 文書名：シフト自動作成デモアプリ 要件定義書
- 対象バージョン：MVP
- 作成日：2026-08-01
- 対象システム：shift-scheduler

## 2. システム概要

本システムは、従業員情報、希望休、必要人数をもとに、
1か月分の勤務シフトを自動生成するデモアプリである。

管理者は、生成されたシフトを確認・手動修正し、
制約違反を検証したうえでCSVとして出力できる。

## 3. システムの目的

- シフト作成作業を効率化する
- 希望休や勤務条件の確認漏れを防止する
- 必要人数と責任者配置を自動的に確認する
- 従業員ごとの勤務日数の偏りを抑える
- 手動変更後の制約違反を検出する

## 4. 想定利用者

### 4.1 管理者

以下の操作を行う。

- 従業員情報の登録・編集
- 希望休の登録
- 必要人数の設定
- シフトの自動生成
- シフトの手動変更
- 制約違反の確認
- CSV出力

MVPでは従業員本人による操作は対象外とする。

## 5. 業務前提

- 対象は単一店舗または単一部署とする
- 従業員数は10人程度とする
- シフト作成期間は1か月単位とする
- シフト区分は早番・遅番の2種類とする
- 原則として各シフトの必要人数は2人とする
- 1人は1日につき最大1シフトとする
- 希望休には勤務を割り当てない
- 1週間は月曜日から日曜日までとする
- 1週間の勤務日数は最大5日とする
- 連続勤務日数は最大5日とする
- 各シフトに責任者を最低1人配置する
- 契約勤務日数は必須一致ではなく目標値とする
- 連続勤務判定は対象月内のみとする

## 6. 機能要件

### FR-01 従業員管理

管理者は従業員情報を登録・編集・無効化できる。

#### 登録項目

- 従業員ID
- 氏名
- 責任者資格の有無
- 契約勤務日数
- 早番勤務可否
- 遅番勤務可否
- 有効状態

#### 入力条件

- 従業員IDは重複不可とする
- 氏名は必須とする
- 契約勤務日数は0以上31以下とする
- 早番・遅番の少なくとも一方を勤務可能とする
- 登録済み従業員は原則として物理削除せず、無効化する

### FR-02 希望休管理

管理者は対象月と従業員を指定し、希望休を登録・変更・削除できる。

#### 入力条件

- 対象月内の日付のみ登録できる
- 同一従業員・同一日付の重複登録は不可とする
- 無効な従業員には新規登録できない

### FR-03 必要人数設定

管理者は日付・シフトごとに必要人数を設定できる。

#### 設定項目

- 対象日
- シフト区分
- 必要人数
- 必要責任者数

#### 初期値

- 早番必要人数：2人
- 遅番必要人数：2人
- 必要責任者数：各シフト1人

#### 入力条件

- 必要人数は0以上とする
- 必要責任者数は0以上とする
- 必要責任者数は必要人数以下とする

### FR-04 入力データ事前検証

シフト生成前に、入力データが生成可能な状態か検証する。

#### 検証項目

- 有効な従業員が存在するか
- 責任者が存在するか
- 必要人数設定が全日・全シフトに存在するか
- 各日・各シフトに必要人数分の勤務可能者がいるか
- 各日・各シフトに必要数の責任者候補がいるか
- 必要勤務枠と契約勤務日数合計に大きな差がないか

### FR-05 シフト自動生成

管理者は対象月を指定し、1か月分のシフトを自動生成できる。

生成処理は、ハード制約をすべて満たしたうえで、
契約勤務日数との差が小さくなる配置を探索する。

### FR-06 シフト表示

生成されたシフトを日付別に表示する。

#### 表示項目

- 日付
- 曜日
- 早番配置者
- 遅番配置者
- 制約状態

### FR-07 従業員別勤務集計

従業員ごとに以下を表示する。

- 契約勤務日数
- 割当勤務日数
- 契約勤務日数との差
- 早番回数
- 遅番回数
- 最大連続勤務日数

### FR-08 制約違反表示

シフト表に制約違反がある場合、違反内容を一覧表示する。

違反には次の情報を含める。

- 重要度
- 制約ID
- 対象日
- シフト区分
- 対象従業員
- メッセージ

### FR-09 手動変更

管理者は生成済みシフトの配置者を追加・削除できる。

変更後はすべての制約を再検証する。

- エラーがある場合は保存不可とする
- 警告のみの場合は保存可能とする
- 手動変更された配置には手動変更フラグを付ける

### FR-10 CSV出力

管理者は以下のCSVを出力できる。

- シフト明細CSV
- 従業員別勤務集計CSV

## 7. ハード制約

ハード制約は、シフト生成時および保存時に必ず満たす条件とする。

| 制約ID | 制約名             | 内容                                      |
| ------ | ------------------ | ----------------------------------------- |
| HC-01  | 1日1シフト制約     | 1人は同じ日に複数シフトへ配置できない     |
| HC-02  | 希望休制約         | 希望休の日には配置できない                |
| HC-03  | 勤務可能シフト制約 | 勤務不可のシフトには配置できない          |
| HC-04  | 必要人数制約       | 各日・各シフトの必要人数を満たす          |
| HC-05  | 責任者配置制約     | 各日・各シフトに必要数の責任者を配置する  |
| HC-06  | 週間勤務日数制約   | 月曜日から日曜日までの勤務を最大5日とする |
| HC-07  | 連続勤務制約       | 6日以上連続して勤務させない               |
| HC-08  | 有効従業員制約     | 無効な従業員をシフトへ配置しない          |

## 8. ソフト制約

ソフト制約は、必須条件を満たしたうえで可能な限り改善する条件とする。

| 制約ID | 制約名             | 内容                               | MVPでの扱い    |
| ------ | ------------------ | ---------------------------------- | -------------- |
| SC-01  | 契約勤務日数近似   | 割当日数を契約勤務日数に近づける   | 最適化対象     |
| SC-02  | 最大乖離抑制       | 一部従業員への不足・超過集中を防ぐ | 最適化対象     |
| SC-03  | 早番・遅番偏り抑制 | 特定シフトへの偏りを抑える         | 集計・警告のみ |
| SC-04  | 責任者勤務偏り抑制 | 責任者勤務の集中を抑える           | 集計・警告のみ |

## 9. エラー・警告定義

### 9.1 エラー

エラーが存在するシフトは保存・確定できない。

| エラーID | 内容                                      |
| -------- | ----------------------------------------- |
| ER-01    | 必要人数を満たしていない                  |
| ER-02    | 必要な責任者が配置されていない            |
| ER-03    | 希望休の日に配置されている                |
| ER-04    | 同一人物が1日に複数シフトへ配置されている |
| ER-05    | 1週間に6日以上勤務している                |
| ER-06    | 6日以上連続勤務している                   |
| ER-07    | 勤務不可シフトに配置されている            |
| ER-08    | 無効な従業員が配置されている              |

### 9.2 警告

警告が存在しても保存できるが、管理者による確認を必要とする。

| 警告ID | 内容                                   |
| ------ | -------------------------------------- |
| WR-01  | 契約勤務日数との差が大きい             |
| WR-02  | 早番または遅番に勤務が偏っている       |
| WR-03  | 責任者勤務が特定従業員に集中している   |
| WR-04  | 必要勤務枠と契約勤務日数合計に差がある |

## 10. 自動生成結果

自動生成処理は以下の状態を返す。

| 状態       | 内容                               |
| ---------- | ---------------------------------- |
| OPTIMAL    | 目的関数上、最適な解が見つかった   |
| FEASIBLE   | 条件を満たす解が見つかった         |
| INFEASIBLE | 条件を満たす解が存在しない         |
| UNKNOWN    | 制限時間内に結果を確定できなかった |

OPTIMALまたはFEASIBLEの場合のみ、生成結果を保存できる。

## 11. 非機能要件

### 11.1 操作性

- 管理者が画面の順序に沿って操作できること
- 入力エラーの理由を具体的に表示すること
- データが存在しない場合も画面が停止しないこと

### 11.2 性能

- 従業員10人、1か月、2シフトの条件で実用的な時間内に生成すること
- 自動生成処理には制限時間を設定すること
- MVPでは制限時間を30秒以内とする

### 11.3 保守性

- 画面、DB処理、制約判定、最適化処理を分離する
- 制約判定処理は自動生成後と手動変更後で共通利用する
- SQLを画面コードへ直接記述しない

### 11.4 データ管理

- データはSQLiteへ保存する
- DBファイルはGit管理対象外とする
- サンプルデータは初期化処理から再現できるようにする

### 11.5 対応環境

- Python 3.11以上
- Streamlit対応ブラウザ
- ローカル環境またはStreamlit Community Cloud

## 12. MVP対象外

以下はMVPでは実装しない。

- ログイン・権限管理
- 従業員本人による希望休入力
- 複数店舗・複数部署
- 夜勤
- 勤務開始・終了時刻
- 休憩時間
- 労働時間集計
- 給与計算
- 有給休暇管理
- シフト交換申請
- メール・チャット通知
- 欠勤時の部分再最適化
- 前月末からの連続勤務判定
- 翌月初まで含めた連続勤務判定
- 手動配置を固定した再生成
- 法令への完全準拠判定
- AIや需要予測による必要人数算出

## 13. 基本業務フロー

1. 管理者が従業員情報を登録する
2. 対象月の希望休を登録する
3. 日付・シフトごとの必要人数を設定する
4. 入力データの事前検証を行う
5. エラーがなければシフトを自動生成する
6. 月間シフト表と従業員別集計を確認する
7. 必要に応じてシフトを手動変更する
8. 変更後の制約を再検証する
9. エラーがなければ変更を保存する
10. シフト明細と勤務集計をCSV出力する

## 14. MVP受入条件

以下をすべて満たした場合、MVP完成とする。

- 従業員を画面から登録・編集・無効化できる
- 従業員ごとに希望休を登録・削除できる
- 1か月分の必要人数を設定できる
- 入力データの不足や矛盾を検出できる
- ハード制約を満たすシフトを自動生成できる
- 生成結果を月間シフト表として表示できる
- 従業員別勤務集計を表示できる
- 生成済みシフトを手動変更できる
- 手動変更後の制約違反を検出できる
- ハード制約違反がある変更は保存できない
- シフト明細CSVを出力できる
- 従業員別集計CSVを出力できる
- 正常系テストでハード制約違反が0件となる

## 15. 要件優先度

### Must

- 従業員管理
- 希望休管理
- 必要人数設定
- 入力データ事前検証
- シフト自動生成
- 全ハード制約
- 制約違反表示
- 手動変更
- CSV出力

### Should

- 契約勤務日数との差の最小化
- 最大乖離の抑制
- 従業員別集計
- 分かりやすい生成不能理由

### Could

- 早番・遅番の偏り警告
- 責任者勤務の偏り警告
- 生成履歴
- 勤務状況のグラフ表示

### Won't

- ログイン
- 複数店舗
- 給与計算
- 通知
- 欠勤時の部分再最適化
