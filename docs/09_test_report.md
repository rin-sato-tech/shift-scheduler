## 2. 実施概要

v1.0.0で確認した既存機能に加え、v1.1.0で追加・変更した次の機能を対象として、追加テストと回帰テストを実施した。

- 希望休のカレンダー選択
- 複数日の希望休一括登録・削除
- 日付別月間シフト表示
- 従業員別月間シフト表示
- 早番・遅番・休みの色分け
- 手動変更マークの表示
- 従業員別月間シフト表のCSV出力
- 個人用シフトカレンダーのCSV出力
- 既存機能の回帰確認

テスト方法は次のとおりである。

- pytestによる自動テスト
- Streamlit画面を使用したUI手動テスト
- CSVファイルの内容確認
- DB整合性確認
- 一連の操作を行う統合テスト

### 6.5 シフト自動生成

自動テストでは、次の内容を確認した。

- 正常な入力条件でシフトを生成できる
- 希望休の従業員を対象日に配置しない
- 日付・シフトごとの必要人数を満たす
- 必要責任者数を満たす
- 1週間の勤務日数が5日以内となる
- 6日以上の連続勤務を回避する
- 契約勤務日数に合わせて勤務日数を配分できる
- 自動生成された配置の`is_manual`が`False`となる
- 目的関数値、最大乖離、乖離合計を取得・保存できる
- 生成履歴を保存できる
- 保存されたシフトを生成履歴へ関連付けられる
- 再生成時に対象月の保存済みシフトを置き換えられる

手動テストでは、生成されたシフトについて次を確認した。

- 勤務不可として設定したシフトへの配置がない
- 無効化された従業員の配置がない

ただし、勤務不可従業員または無効従業員が配置候補に含まれる条件を意図的に作成した個別の自動テストは実施していない。

また、目的関数について、最大乖離を最優先で最小化し、最大乖離が同じ場合に乖離合計を最小化する優先順位は、実装内容を確認しているが、複数の解を比較する専用テストは実施していない。

#### 結果

実施した自動テストおよび手動テストの範囲では合格した。

目的関数の優先順位については未検証であり、今後の自動テスト追加候補とする。

## 15. リスクと留意事項

### 15.1 SQLite

SQLiteを使用しているため、多数利用者による同時書込みには適していない。

本バージョンはローカル・単一利用者向けのデモとする。

### 15.2 月境界

週5日制約と連続勤務制約は、対象月内のデータだけを使用する。

前月末および翌月初の勤務は考慮しない。

### 15.3 Solver

`FEASIBLE`は制約を満たすが、最適性が証明された状態ではない。

`UNKNOWN`の場合は、探索時間を延ばすか入力条件を見直す必要がある。

### 15.4 再生成

再生成すると、対象月の保存済みシフトと手動変更が新しい生成結果へ置き換わる。
