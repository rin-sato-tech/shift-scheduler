### 6.5 シフト自動生成

### 6.6 Solver状態

自動テストでは、次のSolver状態を確認した。

| 状態                      | 確認内容                                                                 | 結果 |

| `INFEASIBLE`              | 制約を満たす解が存在しない場合に、配置を返さず生成失敗として扱う         | 合格 |

ただし、`OPTIMAL`と`FEASIBLE`をそれぞれ意図的に発生させ、個別に処理を確認するテストは実施していない。

次の状態は、自動テストおよび手動テストでは未確認である。

| 状態            | 確認状況 |
| --------------- | -------- |
| `MODEL_INVALID` | 未実施   |
| `UNKNOWN`       | 未実施   |

また、`INFEASIBLE`の場合に生成された配置が空となることは確認した。

`INFEASIBLE`、`MODEL_INVALID`、`UNKNOWN`の場合に、目的関数値、最大乖離、乖離合計がすべて未設定となることを確認する専用テストは実施していない。

#### 結果

実行可能解が得られる正常系と、`INFEASIBLE`となる異常系については合格した。

`OPTIMAL`と`FEASIBLE`の個別確認、ならびに`MODEL_INVALID`と`UNKNOWN`の確認は未実施である。

### 6.13 トランザクション

自動テストでは、シフト自動生成結果をDBへ保存する際のトランザクション処理について、次の内容を確認した。

| 確認項目               | 確認内容                                                                 | 結果 |
| ---------------------- | ------------------------------------------------------------------------ | ---- |
| 正常保存               | 生成履歴と複数のシフト配置をまとめて保存できる                           | 合格 |
| 生成履歴の保存         | Solver状態、目的関数値、最大乖離、乖離合計を保存できる                   | 合格 |
| 関連付け               | 保存したシフト配置を同じ生成履歴IDへ関連付けられる                       | 合格 |
| 月間シフトの置換       | 同じ対象月で再生成した場合に、既存シフトを新しい生成結果へ置き換えられる | 合格 |
| 生成履歴の保持         | 再生成後も過去の生成履歴を削除せず保持できる                             | 合格 |
| 対象月の分離           | 再生成時に、指定した対象月のシフトだけを置き換えられる                   | 合格 |
| 対象月外データの拒否   | 指定した対象月外の日付を含むシフトについて、保存処理を開始せず拒否できる | 合格 |
| 例外時のロールバック   | シフトの一括登録中にDB制約違反が発生した場合に、処理全体を取り消せる     | 合格 |
| 不完全な生成履歴の防止 | 保存途中で例外が発生した場合に、生成履歴だけがDBへ残らない               | 合格 |
| 不完全なシフトの防止   | 保存途中で例外が発生した場合に、一部のシフトだけがDBへ残らない           | 合格 |

ロールバックのテストでは、同じ従業員を同じ日に早番・遅番の両方へ登録する不正な配置を渡し、DBの一意制約違反を意図的に発生させた。

その結果、例外発生後に次の状態となることを確認した。

- 生成履歴の登録件数が0件である
- シフト配置の登録件数が0件である
- 保存処理の途中結果がDBに残っていない

次の項目については、専用の自動テストを実施していない。

| 確認項目                                                                                 | 結果   |
| ---------------------------------------------------------------------------------------- | ------ |
| 既存シフトが保存されている状態で置換処理に失敗した場合に、置換前のシフトが保持されること | 未実施 |
| 手動変更の保存中にDB例外が発生した場合のロールバック                                     | 未実施 |
| 対象月以外のシフトが置換失敗後も保持されること                                           | 未実施 |

なお、制約違反を含む手動変更については、DB保存前の検証によって保存を拒否し、既存シフトを保持できることを別の自動テストで確認している。ただし、これはDB書込み途中の例外によるロールバックとは異なる。

#### 結果

正常保存、月間シフトの置換および新規保存時の例外ロールバックに関する自動テストは、すべて合格した。

既存シフトが存在する状態での置換失敗、および手動変更保存時のDB例外については、今後の自動テスト追加候補とする。

## 14. リスクと留意事項

### 14.1 SQLite

SQLiteを使用しているため、多数利用者による同時書込みには適していない。

本バージョンはローカル・単一利用者向けのデモとする。

### 14.2 月境界

週5日制約と連続勤務制約は、対象月内のデータだけを使用する。

前月末および翌月初の勤務は考慮しない。

### 14.3 Solver

`FEASIBLE`は制約を満たすが、最適性が証明された状態ではない。

`UNKNOWN`の場合は、探索時間を延ばすか入力条件を見直す必要がある。

### 14.4 再生成

再生成すると、対象月の保存済みシフトと手動変更が新しい生成結果へ置き換わる。
