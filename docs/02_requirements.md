## 2. 本書の目的

本書は、シフト自動作成デモが満たすべき機能要件、業務ルール、非機能要件、制約および受入条件を定義する。

プロジェクトの背景、想定利用者、対象業務の全体像は`01_overview.md`に記載する。

システム構成とモジュール設計は`03_system_design.md`、データベースとPythonモデルの定義は`04_data_definition.md`、OR-Toolsを用いた制約モデルの詳細は`05_schedule_constraints.md`に記載する。

## 3. システムの目的

本システムは、従業員情報、希望休、必要人数をもとに、1か月分の勤務シフトを自動生成するWebアプリケーションである。

次の目的を達成する。

- シフト作成作業を効率化する
- 希望休や勤務条件の確認漏れを防止する
- 必要人数と責任者配置を自動的に確認する
- 従業員ごとの勤務日数の偏りを抑える
- 自動生成できない理由を利用者へ示す
- 自動生成後の手動調整を可能にする
- 手動変更によって生じた制約違反を検出する
- 確定したシフトをCSVとして出力する

---

## 4. 想定利用者

### 4.1 シフト作成担当者

本システムの主な利用者は、小規模事業所において月間シフトを作成する担当者とする。

利用者は次の操作を行う。

- 従業員情報の登録・編集
- 従業員の有効・無効状態の変更
- 希望休の登録・削除
- 必要人数と必要責任者数の設定
- 入力データの検証
- シフトの自動生成
- 生成結果の確認
- シフトの手動変更
- 変更後の制約確認
- CSV出力

### 4.2 対象外の利用者

現在のバージョンでは、次の利用者による操作は対象外とする。

- 従業員本人による希望休入力
- 複数の管理者による同時編集
- 閲覧専用利用者
- 複数店舗を統括する管理者

認証および権限管理は実装しない。

## 5. 業務前提

本システムでは、次の業務条件を前提とする。

| 項目         | 前提                          |
| ------------ | ----------------------------- |
| 対象組織     | 単一店舗または単一部署        |
| 従業員数     | 数名から数十名程度            |
| 作成期間     | 1か月単位                     |
| シフト区分   | 早番・遅番                    |
| 1日の配置    | 1人につき最大1シフト          |
| 希望休       | 日単位                        |
| 週の区切り   | ISO週に基づく月曜日から日曜日 |
| 週間勤務日数 | 最大5日                       |
| 連続勤務日数 | 最大5日                       |
| 契約勤務日数 | 必須一致ではなく最適化目標    |
| 連続勤務判定 | 対象月内のみ                  |
| データ保存   | SQLite                        |
| 利用環境     | ローカル環境                  |

必要人数と必要責任者数は、固定値ではなく日付・シフトごとに設定する。

## 7. 機能要件

## 7.1 FR-01 従業員管理

システムは、シフト作成に必要な従業員情報を登録・編集できること。

### 7.1.1 登録項目

- 従業員ID
- 氏名
- 責任者区分
- 月間契約勤務日数
- 早番勤務可否
- 遅番勤務可否
- 有効状態

### 7.1.2 入力条件

- 従業員IDは必須とする
- 従業員IDは重複不可とする
- 氏名は必須とする
- 空白のみの氏名は登録不可とする
- 契約勤務日数は0以上31以下とする
- 早番または遅番の少なくとも一方を勤務可能とする
- 新規登録時は有効状態とする

### 7.1.3 編集

システムは、登録済み従業員について次の項目を編集できること。

- 氏名
- 責任者区分
- 契約勤務日数
- 早番勤務可否
- 遅番勤務可否

従業員IDは登録後に変更しない。

### 7.1.4 有効状態

- 従業員を無効化できること
- 無効化された従業員を再有効化できること
- 従業員を通常操作では物理削除しないこと
- 無効な従業員は新しい自動生成の候補に含めないこと
- 過去に登録された希望休やシフトは履歴確認のため保持すること

---

## 7.2 FR-02 希望休管理

システムは、対象月と従業員を指定して希望休を登録できること。

### 7.2.1 登録条件

- 希望休は日単位で登録する
- 対象月内の日付のみ登録できる
- 同一従業員・同一日付の重複登録は不可とする
- 無効な従業員には新しい希望休を登録できない
- シフト区分別の希望休は扱わない

### 7.2.2 一覧表示

システムは、対象月の希望休を一覧表示できること。

一覧には次の情報を表示する。

- 希望日
- 曜日
- 従業員ID
- 氏名
- 従業員の有効状態

### 7.2.3 絞り込み

希望休一覧を従業員単位で絞り込めること。

### 7.2.4 削除

登録済みの希望休を物理削除できること。

---

## 7.3 FR-03 必要人数設定

システムは、日付・シフトごとに必要人数と必要責任者数を設定できること。

### 7.3.1 設定項目

- 対象日
- シフト区分
- 必要人数
- 必要責任者数

### 7.3.2 シフト区分

設定可能なシフト区分は次の2種類とする。

- `early`：早番
- `late`：遅番

### 7.3.3 入力条件

- 必要人数は0以上とする
- 必要責任者数は0以上とする
- 必要責任者数は必要人数以下とする
- 対象月内の日付のみ登録できる
- 同一日付・同一シフトの設定は1件とする

### 7.3.4 一括設定

対象月の全日・全シフトに対し、同じ必要人数と必要責任者数を一括設定できること。

### 7.3.5 個別調整

一括設定後に、日付・シフト単位で値を変更できること。

### 7.3.6 保存

対象月の設定をまとめて保存できること。

既存設定がある場合は、日付・シフトの組み合わせを基準に更新する。

---

## 7.4 FR-04 入力データ事前検証

システムは、シフト生成前に入力データを検証できること。

### 7.4.1 検証項目

| ルールID | 検証内容                                       | 重大度  |
| -------- | ---------------------------------------------- | ------- |
| PV-01    | 有効な従業員が存在するか                       | error   |
| PV-02    | 必要な場合に有効な責任者が存在するか           | error   |
| PV-03    | 全日・全シフトの必要人数設定が存在するか       | error   |
| PV-04    | 必要人数分の勤務可能者が存在するか             | error   |
| PV-05    | 必要数の責任者候補が存在するか                 | error   |
| PV-06    | 契約勤務日数合計が必要勤務枠を下回っていないか | warning |
| PV-07    | 契約勤務日数合計が必要勤務枠を上回っていないか | warning |
| PV-08    | 契約勤務日数が対象月の日数を超えていないか     | warning |
| PV-09    | 必要人数設定の値が正しいか                     | error   |
| PV-10    | 週5日上限を考慮した最大配置数が足りるか        | error   |

### 7.4.2 検証時の勤務可能者

勤務可能者は、次の条件をすべて満たす従業員とする。

- 有効状態である
- 対象日が希望休ではない
- 対象シフトを勤務可能である

### 7.4.3 検証結果

検証結果は、エラーを先、警告を後に並べて表示する。

同じ重大度では、対象日、シフト区分、ルールIDを基準に並べる。

### 7.4.4 生成可否

事前検証で`error`が1件以上存在する場合、シフト生成を実行できないこと。

`warning`のみの場合は、内容を表示したうえで生成を許可する。

---

## 7.5 FR-05 シフト自動生成

システムは、対象月を指定して月間シフトを自動生成できること。

### 7.5.1 入力データ

生成処理では次のデータを使用する。

- 有効な従業員
- 従業員の責任者区分
- 従業員の契約勤務日数
- 従業員の勤務可能シフト
- 対象月の希望休
- 対象月の必要人数
- 対象月の必要責任者数

### 7.5.2 生成方式

Google OR-ToolsのCP-SAT Solverを使用する。

従業員、日付、シフトの組み合わせを0または1の決定変数として表現する。

### 7.5.3 ハード制約

生成結果は、7章に定めるハード制約をすべて満たすこと。

### 7.5.4 最適化

ハード制約を満たす解の中から、次の値が小さくなる配置を探索する。

1. 従業員ごとの契約勤務日数との最大乖離
2. 全従業員の契約勤務日数との乖離合計

### 7.5.5 制限時間

生成処理には実行時間の上限を設定できること。

通常利用時の標準上限は30秒以内を想定する。

### 7.5.6 Solver状態

生成処理は次のいずれかの状態を返す。

| 状態            | 内容                               |
| --------------- | ---------------------------------- |
| `OPTIMAL`       | 目的関数上の最適解が見つかった     |
| `FEASIBLE`      | 制約を満たす解が見つかった         |
| `INFEASIBLE`    | 制約を満たす解が存在しない         |
| `MODEL_INVALID` | 最適化モデルの定義が不正           |
| `UNKNOWN`       | 制限時間内に状態を確定できなかった |

### 7.5.7 保存条件

- `OPTIMAL`または`FEASIBLE`の場合のみシフトを保存する
- 生成履歴を保存する
- 対象月の既存シフトを新しい生成結果で置き換える
- 自動生成された配置は`is_manual=False`とする

---

## 7.6 FR-06 生成結果表示

システムは、生成結果を画面上で確認できること。

### 7.6.1 Solver結果

次の情報を表示する。

- Solver状態
- 目的関数値
- 最大乖離
- 乖離合計
- 生成成功・失敗

### 7.6.2 月間シフト表

日付ごとに次の情報を表示する。

- 日付
- 曜日
- 早番配置者
- 遅番配置者

### 7.6.3 配置明細

1配置を1行として次の情報を表示する。

- 日付
- 曜日
- シフト
- 従業員ID
- 氏名
- 責任者区分
- 手動変更の有無

---

## 7.7 FR-07 従業員別勤務集計

システムは、対象月の勤務状況を従業員ごとに集計できること。

表示項目は次のとおりとする。

- 従業員ID
- 氏名
- 契約勤務日数
- 割当勤務日数
- 契約勤務日数との差
- 早番回数
- 遅番回数
- 最大連続勤務日数
- 責任者配置回数

差は次の考え方で算出する。

```text
割当勤務日数 - 契約勤務日数
```

---

## 7.8 FR-08 制約違反・警告表示

システムは、検証で発見した問題を一覧表示できること。

### 7.8.1 表示情報

各検証結果は、必要に応じて次の情報を持つ。

- 重大度
- ルールID
- メッセージ
- 対象日
- シフト区分
- 従業員ID

### 7.8.2 重大度

| 重大度    | 意味                           |
| --------- | ------------------------------ |
| `error`   | 生成または保存を妨げる問題     |
| `warning` | 処理は可能だが確認が必要な状態 |

### 7.8.3 表示方法

- エラー件数を表示する
- 警告件数を表示する
- 詳細を展開表示できる
- 問題がない場合は正常であることを表示する

---

## 7.9 FR-09 シフト手動変更

システムは、保存済みシフトを従業員・日付単位で変更できること。

### 7.9.1 変更内容

変更後の配置として次を選択できる。

- 早番
- 遅番
- 休み

### 7.9.2 編集案

- 変更内容は即時にDBへ保存しない
- Streamlitのセッション上に編集案として保持する
- 複数の変更を一時的に保持できる
- 保存済みシフトの原本と編集案を分けて保持する

### 7.9.3 手動変更フラグ

手動で早番または遅番へ変更された配置は、`is_manual=True`とする。

休みへの変更は、該当する配置を編集案から除外する。

### 7.9.4 再検証

編集案に対して、月間シフト全体の制約を再検証する。

- エラーがある場合は保存不可とする
- 警告のみの場合は保存可能とする
- 問題がない場合は保存可能とする

### 7.9.5 差分表示

原本と編集案を比較し、次の情報を表示する。

- 日付
- 曜日
- 従業員ID
- 氏名
- 変更前
- 変更後

### 7.9.6 保存

保存時は対象月のシフト全体を一括置換する。

既存データの削除と新しい配置の登録は同一トランザクション内で実行する。

### 7.9.7 破棄

編集案を破棄し、保存済みシフトへ戻せること。

---

## 7.10 FR-10 CSV出力

システムは、対象月の保存済みシフトをCSV出力できること。

### 7.10.1 出力種類

| 出力             | 内容                                 |
| ---------------- | ------------------------------------ |
| 月間シフト表     | 日付・曜日・早番配置者・遅番配置者   |
| 配置明細         | 1配置1行の詳細データ                 |
| 従業員別勤務集計 | 従業員単位の勤務回数・差・連続勤務等 |

### 7.10.2 文字コード

CSVはUTF-8 BOM付きで出力する。

### 7.10.3 月間シフト表

手動変更された配置者名には`※`を付ける。

### 7.10.4 配置明細

手動変更の有無を列として出力する。

### 7.10.5 ファイル名

対象月とデータ種別を含むファイル名を生成する。

例：

```text
shift_schedule_202608.csv
shift_detail_202608.csv
shift_summary_202608.csv
```

システムは、アプリ起動時および各ページの直接表示時にDBを初期化できること。

初期化処理は、存在しないテーブルだけを作成し、既存データを削除しないこと。

## 7.12 FR-12 DB整合性確認

システムは、補助スクリプトによって次の整合性を確認できること。

- 外部キー違反
- 同一従業員の同日重複配置
- 不正なシフト区分
- 必要なテーブルの存在

整合性違反がある場合は、終了コード1を返すこと。

## 8. ハード制約

ハード制約は、シフト生成時および手動変更後の保存時に必ず満たす条件とする。

| 制約ID | 制約名             | 内容                                             |
| ------ | ------------------ | ------------------------------------------------ |
| HC-01  | 1日1シフト制約     | 1人は同じ日に複数シフトへ配置できない            |
| HC-02  | 希望休制約         | 希望休の日には配置できない                       |
| HC-03  | 勤務可能シフト制約 | 勤務不可のシフトには配置できない                 |
| HC-04  | 必要人数制約       | 日付・シフトごとの配置人数を必要人数と一致させる |
| HC-05  | 責任者配置制約     | 日付・シフトごとの責任者数を必要数以上とする     |
| HC-06  | 週間勤務日数制約   | 月曜日から日曜日までの勤務日数を最大5日とする    |
| HC-07  | 連続勤務制約       | 6日以上連続して勤務させない                      |
| HC-08  | 有効従業員制約     | 無効な従業員を新しいシフトへ配置しない           |

### 8.1 月境界

週間勤務日数と連続勤務日数は、現在のバージョンでは対象月内のデータだけを用いて判定する。

前月末および翌月初の勤務は考慮しない。

## 9. 警告基準

警告が存在してもシフトを保存できるが、利用者による確認を必要とする。

| 警告ID | 内容                                          |
| ------ | --------------------------------------------- |
| WR-01  | 契約勤務日数との差の絶対値が3日以上           |
| WR-02  | 両シフト勤務可能者の早番・遅番回数差が5回以上 |
| WR-03  | 責任者間の配置回数差が5回以上                 |
| WR-04  | 必要勤務枠と契約勤務日数合計が一致しない      |

警告値は業務ルールとして固定しており、現在は画面から変更できない。

---

## 10. ソフト制約・最適化対象

ソフト制約は、ハード制約を満たしたうえで可能な限り改善する条件とする。

| 制約ID | 制約名           | 内容                                 | 現在の扱い |
| ------ | ---------------- | ------------------------------------ | ---------- |
| SC-01  | 契約勤務日数近似 | 割当日数を契約勤務日数へ近づける     | 最適化     |
| SC-02  | 最大乖離抑制     | 一部従業員への不足・超過集中を抑える | 最適化     |
| SC-03  | シフト偏り抑制   | 早番または遅番への偏りを抑える       | 集計・警告 |
| SC-04  | 責任者偏り抑制   | 責任者配置の集中を抑える             | 集計・警告 |

現在の目的関数では、契約勤務日数との差を主な最適化対象とする。

早番・遅番の偏りと責任者配置の偏りは、生成結果の集計および警告として扱う。

---

## 11. エラー定義

エラーが存在するシフトは保存できない。

| エラーID | 内容                                      |
| -------- | ----------------------------------------- |
| ER-01    | 必要人数を満たしていない                  |
| ER-02    | 必要な責任者が配置されていない            |
| ER-03    | 希望休の日に配置されている                |
| ER-04    | 同一人物が1日に複数シフトへ配置されている |
| ER-05    | 1週間に6日以上勤務している                |
| ER-06    | 6日以上連続勤務している                   |
| ER-07    | 勤務不可シフトに配置されている            |
| ER-08    | 無効な従業員が配置されている              |
| ER-09    | 不明な従業員IDが配置に含まれている        |
| ER-10    | 不正なシフト区分が含まれている            |

エラーIDと内部の検証ルールIDは、実装上の都合により異なる場合がある。

## 12. 非機能要件

## 12.1 操作性

- 画面の順序に沿って操作できること
- トップ画面に基本的な操作順を表示すること
- 対象年と対象月を共通形式で選択できること
- 入力エラーの理由を具体的に表示すること
- 成功・警告・エラーを区別して表示すること
- データがない場合に適切な案内を表示すること
- 保存後の再描画でも結果メッセージを確認できること

## 12.2 性能

- 数名から数十名、1か月、2シフトの条件で利用できること
- Solverに実行時間の上限を設定できること
- 通常のデモ条件では30秒以内の生成を目標とすること
- 大量データを前提とした性能保証は行わない

## 12.3 信頼性

- 外部キー制約を有効にすること
- 重複登録をDB制約でも防止すること
- 月間シフトの置換をトランザクション内で行うこと
- 保存途中の失敗時にロールバックされること
- 生成成功時のみシフトを保存すること
- 手動変更後は再検証を行うこと

## 12.4 保守性

- 画面、業務処理、DB処理、検証処理を分離すること
- SQLを画面コードへ直接記述しないこと
- DBレコードをPythonモデルへ変換すること
- 共通UI処理を再利用できること
- 表示用DataFrame変換を画面から分離すること
- 型ヒントを使用すること
- 主要処理に自動テストを用意すること

## 12.5 可搬性

- Pythonが利用できる環境で実行できること
- macOS、Windows、Linuxでのローカル実行を想定する
- DBパスはプロジェクトルートを基準に決定すること
- Excelで開けるCSVを出力すること

## 12.6 セキュリティ

現在はローカルデモであるため、次を前提とする。

- インターネットへ公開しない
- 信頼できる利用者が使用する
- 実在する個人の機密情報を保存しない
- 認証・権限管理を必要とする本番用途には使用しない

## 12.7 テスト

- pytestで自動テストを実行できること
- テスト用DBをアプリ用DBから分離すること
- 正常系と異常系を確認すること
- Repository、サービス、検証、生成、手動変更、出力を確認すること
- 一連の操作を確認する統合テストを用意すること
- DB整合性を補助スクリプトで確認できること

## 13. データ要件

- 日付は`YYYY-MM-DD`形式でDBへ保存する
- 対象月は`YYYY-MM`形式で扱う
- 日時はタイムゾーン付きISO 8601形式で保存する
- 真偽値はSQLite上で`0`または`1`として保存する
- シフト区分は`early`または`late`とする
- 同一従業員・同一日のシフトは1件までとする
- 従業員は物理削除せず有効状態で管理する
- 希望休は物理削除を許可する
- 対象月のシフトは一括置換できること

詳細は`04_data_definition.md`に記載する。

---

## 14. 対象外

現在のバージョンでは、次を対象外とする。

- 従業員本人による希望休入力
- ログイン・認証
- 利用者ごとの権限管理
- 複数店舗・複数部署
- 複数利用者による同時編集
- 早番・遅番以外のシフト種別
- 時刻単位の勤務管理
- 休憩時間管理
- 週40時間の実労働時間計算
- 残業時間の計算
- 勤務間インターバル
- 法定休日の厳密な管理
- 有給休暇残数管理
- 給与計算
- 前月末を含む連続勤務判定
- 生成履歴の一覧・詳細画面
- Excel形式での直接出力
- メールやチャットによる通知
- 外部システム連携
- クラウド上での本番運用
- 監査ログ
- バックアップ・復元画面

## 15. 受入条件

## 15.1 従業員管理

- 有効な従業員を登録できる
- 重複した従業員IDを拒否できる
- 登録済み従業員を編集できる
- 従業員を無効化・再有効化できる
- 勤務可能シフトが0件となる更新を拒否できる

## 15.2 希望休

- 対象月内の希望休を登録できる
- 重複希望休を拒否できる
- 対象月外の日付を拒否できる
- 登録済み希望休を削除できる

## 15.3 必要人数

- 月全体へ一括設定できる
- 日付・シフト単位で調整できる
- 必要責任者数が必要人数を超える値を拒否できる
- 保存後に同じ内容を再取得できる

## 15.4 シフト生成

- 事前検証結果を表示できる
- エラーがある場合は生成を開始しない
- 実行可能な条件ではシフトを生成できる
- 希望休へ配置しない
- 勤務不可シフトへ配置しない
- 必要人数と必要責任者数を満たす
- 週5日上限と最大5連勤を満たす
- 生成結果をDBへ保存できる
- 同じ月を再生成できる

## 15.5 手動変更

- 早番・遅番・休みへ変更できる
- 複数変更を編集案として保持できる
- 変更前後の差分を確認できる
- 制約違反を再検証できる
- エラーがある編集案を保存できない
- 正常な編集案を保存できる
- 編集案を破棄できる

## 15.6 CSV出力

- 月間シフト表を出力できる
- 配置明細を出力できる
- 従業員別勤務集計を出力できる
- Excelで日本語が文字化けしない
- 手動変更の情報を確認できる

## 15.7 品質

- 全自動テストが成功する
- DB整合性確認が成功する
- 主要な手動テストが完了する
- 保存失敗時のロールバックを確認できる
- 既知の未対応事項が文書化されている
