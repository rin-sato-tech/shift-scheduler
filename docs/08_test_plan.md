## 2. 本書の目的

本書は、シフト自動作成デモの品質を確認するためのテスト方針、対象範囲、テストレベル、確認観点、完了基準を定義する。

実際のテスト実施結果は`09_test_report.md`に記載する。

機能要件は`02_requirements.md`、システム構成は`03_system_design.md`、シフト制約の詳細は`05_schedule_constraints.md`に記載する。

---

## 3. テストの目的

本システムのテストでは、主に次を確認する。

- 各画面の主要操作を実行できる
- 不正な入力を適切に拒否できる
- シフト生成前に入力データの不足を検出できる
- OR-Toolsがハード制約を満たすシフトを生成する
- 生成結果を正しく保存できる
- 手動変更後も制約を再検証できる
- エラーがある編集案を保存できない
- 保存処理の途中で失敗してもDBの整合性を維持できる
- CSVの内容と文字コードが正しい
- 主要機能を組み合わせた操作フローを実行できる

## 8. テストデータ方針

### 8.1 正常データ

次を満たすデータを用意する。

- 有効な従業員が複数存在する
- 責任者が複数存在する
- 早番・遅番の両方へ配置可能な従業員がいる
- 早番のみ勤務可能な従業員がいる
- 遅番のみ勤務可能な従業員がいる
- 対象月の全日・全シフトに必要人数が設定されている
- 希望休を考慮しても必要人数を満たせる
- 週5日と最大5連勤を満たす解が存在する

### 8.2 異常データ

次のようなデータを個別に用意する。

- 従業員IDが重複している
- 氏名が空である
- 両シフトとも勤務不可である
- 希望休が重複している
- 希望休が対象月外である
- 必要責任者数が必要人数を超える
- 必要人数設定が不足している
- 有効従業員がいない
- 有効責任者がいない
- 勤務可能者数が不足している
- 責任者候補が不足している
- 週5日上限を考慮すると必要枠を満たせない
- ハード制約を同時に満たす解が存在しない
- 手動変更によって必要人数が不足する
- DB保存途中で例外が発生する

## 9. 自動テストの実行方法

基本コマンド：

```bash
python -m pytest -v
```

実行時間を含めて確認する場合：

```bash
python -m pytest -v --durations=20
```

失敗時の詳細を確認する場合：

```bash
python -m pytest -v --tb=long
```

## 10. 自動テスト方針

### 10.1 テストの独立性

- テスト間でDB状態を共有しない
- テストごとに必要なデータを準備する
- テスト終了後に一時データを残さない
- 実行順序に依存しない
- アプリ用DBをテストで使用しない

### 10.2 外部依存

本システムは外部APIを使用しないため、ネットワーク通信を伴うテストは行わない。

OR-Tools、SQLite、pandasは実際のライブラリを使用する。

### 10.3 再現性

Solverテストでは、原則として次を使用する。

```text
num_search_workers = 1
```

複数ワーカーによる探索結果の揺れを避け、テスト結果の再現性を高める。

## 23. 統合テスト

次の一連の流れを確認する。

1. 従業員を登録する
2. 希望休を登録する
3. 必要人数を設定する
4. 生成前検証を行う
5. シフトを生成する
6. 生成結果を保存する
7. 保存済みシフトを再取得する
8. 従業員別勤務集計を作成する
9. シフトを手動変更する
10. 編集案を再検証する
11. 手動変更を保存する
12. CSVデータを生成する

異常系では、途中でエラーが発生した場合に不完全なデータが残らないことを確認する。

## 24. UI手動テストの実施方法

### 24.1 準備

```bash
streamlit run app.py
```

テスト用データを準備し、各画面をサイドバーから順に操作する。

### 24.2 確認方法

各項目について次を確認する。

- 入力欄が表示される
- 選択肢が正しい
- ボタンの有効・無効が正しい
- 操作後に一覧が更新される
- 成功メッセージが表示される
- エラー時に理由が表示される
- 再描画後も必要なメッセージを確認できる
- 編集中の内容と保存済み内容を区別できる

## 27. 不具合の優先度

| 優先度   | 定義                                 | 例                           |
| -------- | ------------------------------------ | ---------------------------- |
| Critical | データ破損や主要機能の利用不能       | 保存時に既存データが消失する |
| High     | 主要要件またはハード制約を満たさない | 希望休へ配置される           |
| Medium   | 回避可能だが操作・表示に問題がある   | メッセージが不明確           |
| Low      | 軽微な表示・文言の問題               | 余白、表記揺れ               |

CriticalまたはHighの未修正不具合がある場合、公開版として完了扱いにしない。

## 28. 既知の未対応事項

- 生成履歴を画面上で一覧・参照する機能は未実装
- 複数ブラウザ・複数OSでの網羅的UI試験は未実施
- 多数利用者を想定した負荷試験は未実施
- クラウド環境での試験は未実施

これらはv1.0.0の対象外であり、現在の主要機能の完了を妨げるものではない。
