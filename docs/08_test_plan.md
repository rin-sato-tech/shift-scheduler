## 2. 本書の目的

本書は、シフト自動作成デモの品質を確認するためのテスト方針、対象範囲、テストレベル、確認観点、完了基準を定義する。

実際のテスト実施結果は`09_test_report.md`に記載する。

機能要件は`02_requirements.md`、システム構成は`03_system_design.md`、シフト制約の詳細は`05_schedule_constraints.md`に記載する。

---

## 3. テストの目的

本システムのテストでは、主に次を確認する。

- 入力・編集・出力の主要操作を実行できる
- 不正な入力や制約違反を適切に検出できる
- OR-Toolsがハード制約を満たすシフトを生成する
- 自動生成・手動変更・保存処理でDBの整合性を維持できる
- 日付別・従業員別の表示データを正しく生成できる
- 管理用・個人用CSVを正しい内容と形式で出力できる
- 既存機能を含む一連の業務フローを実行できる

## 8. テストデータ方針

### 8.1 正常データ

次を満たすデータを用意する。

- 有効な従業員と責任者が複数存在する
- 早番のみ、遅番のみ、両方勤務可能な従業員が存在する
- 対象月の全日・全シフトに必要人数が設定されている
- 複数従業員に複数日の希望休が登録されている
- 自動生成・手動変更後も制約を満たす配置が存在する
- 自動配置と手動変更配置が混在している
- 30日、31日、2月など月の日数が異なるデータがある

### 8.2 異常データ

次のようなデータを個別に用意する。

- 従業員入力が不正
- 希望休が重複または対象月外
- 無効な従業員へ希望休を登録する
- 必要責任者数が必要人数を超える
- 必要人数設定または勤務可能者が不足する
- ハード制約を同時に満たす解が存在しない
- 手動変更によって制約違反が発生する
- DB保存途中で例外が発生する
- 月初・月末の曜日配置を誤りやすい対象月を使用する

## 9. 自動テストの実行方法

基本コマンド：

```bash
python -m pytest -v
```

実行時間を含めて確認する場合：

```bash
python -m pytest -v --durations=20
```

失敗時の詳細を確認する場合：

```bash
python -m pytest -v --tb=long
```

## 10. 自動テスト方針

### 10.1 テストの独立性

- テスト間でDB状態を共有しない
- テストごとに必要なデータを準備する
- テスト終了後に一時データを残さない
- 実行順序に依存しない
- アプリ用DBをテストで使用しない

### 10.2 外部依存

本システムは外部APIを使用しないため、ネットワーク通信を伴うテストは行わない。

OR-Tools、SQLite、pandasは実際のライブラリを使用する。

### 10.3 再現性

Solverテストでは、原則として次を使用する。

```text
num_search_workers = 1
```

複数ワーカーによる探索結果の揺れを避け、テスト結果の再現性を高める。

- 年をまたぐ月を正しく扱う

## 21. トランザクションテスト

月間シフトの保存では、次を確認する。

- 正常時に既存シフトを削除して新規登録する
- 全件登録後にコミットする
- 登録途中の例外でロールバックする
- 失敗時に既存シフトが残る
- 対象月外の配置を含む場合に更新しない
- 空の配置一覧を適切に扱う
- 生成履歴と配置の保存が一貫する

## 22. 表示変換テスト

### 22.1 日付別月間シフト表

- 対象月の全日付を作成できる
- 早番・遅番配置者を正しく表示できる
- 手動変更マークを表示できる
- 不明な従業員IDを安全に扱える

### 22.2 従業員別月間シフト表

- 行を従業員、列を日付として作成できる
- 日付列を月の日数分作成できる
- 早番、遅番、休みを正しく判定できる
- 手動変更マークを表示できる
- 複数従業員を正しく分離できる
- 配置がない従業員も表示できる
- 30日、31日、2月を正しく扱える

画面上の色分けはStreamlitまたはpandas StylerによるUI処理であるため、手動テストで確認する。

### 22.3 その他の表示変換

- 配置明細を作成できる
- 従業員別勤務集計表を作成できる
- 手動変更差分を作成できる
- 変更がない場合に空のDataFrameを返す

### 22.4 色分け手動テスト

- [ ] 早番が青系で表示される
- [ ] 遅番がオレンジ系で表示される
- [ ] 休みがグレー系で表示される
- [ ] 色分け後も文字を確認できる
- [ ] 従業員ID・氏名列へ勤務色が付かない
- [ ] 手動変更の`※`が消えない
- [ ] 横スクロールして月末まで確認できる

## 23. 統合テスト

次の一連の流れを確認する。

1. 従業員を登録する
2. 複数日の希望休を登録する
3. 必要人数を設定する
4. 生成前検証を行う
5. シフトを生成して保存する
6. 日付別・従業員別の表を確認する
7. シフトを手動変更して再検証・保存する
8. 従業員別表へ手動変更が反映されることを確認する
9. 5種類のCSVデータを作成する
10. 個人用カレンダーが選択した従業員の内容だけを含むことを確認する
11. DB整合性を確認する

異常系では、途中でエラーが発生した場合に不完全なデータが残らないことを確認する。

## 27. 不具合の優先度

| 優先度   | 定義                                 | 例                           |
| -------- | ------------------------------------ | ---------------------------- |
| Critical | データ破損や主要機能の利用不能       | 保存時に既存データが消失する |
| High     | 主要要件またはハード制約を満たさない | 希望休へ配置される           |
| Medium   | 回避可能だが操作・表示に問題がある   | メッセージが不明確           |
| Low      | 軽微な表示・文言の問題               | 余白、表記揺れ               |

CriticalまたはHighの未修正不具合がある場合、公開版として完了扱いにしない。
